2. Workflow-uri critice

2.1 Voice call inbound

Telnyx (client sună +40) → POST /webhook/telnyx/voice
  → TelnyxWebhookController::handleVoice()
  → Creează Call record, validează phone number
  → Returnează TeXML cu stream URL WebSocket
  → MediaStreamHandler stabilește conexiunea
  → RealtimeClient → OpenAI Realtime API (WebSocket)
  → Audio g711_ulaw live în ambele direcții
  → Tool calls: lead capture, product search, callback
  → call.hangup → cost calculat, transcript salvat

2.2 Chat message (webchat / WhatsApp / FB / IG)

Client → POST /api/v1/chatbot/{channel}/message SAU
Meta webhook → ProcessChannelMessage job
  → ChatCompletionService::handle()
  → Stage 1: IntentClassifier (7 tipuri, ~30ms)
  → Stage 2: Hybrid RAG (vector 1536 + FTS RO + RRF + reranker, ~150ms)
  → Stage 3: ConversationStrategy (per-stage policy, ~5ms)
  → Stage 4: Generate + 10-layer anti-hallucination
  → Response JSON/SSE

2.3 Knowledge ingestion

Upload PDF/DOCX/CSV/URL → ProcessKnowledgeDocument job
  → Extract text → Semantic chunking
  → Batch embed (100 chunks/call OpenAI text-embedding-3-small)
  → Insert în knowledge_chunks cu pgvector HNSW
  → tsvector FTS populated prin trigger PostgreSQL
  → Scheduled knowledge:process every minute

🔴 Critical — promise direct nelivrat sau risc de securitate

G1 P0 Stripe billing flow lipsă complet

Promis: planuri lunare/anuale, 7 zile trial, upgrade/downgrade pro-rata, 30% discount ONG, overage automat.

Realitate: Cashier Billable trait există dar NU există: checkout flow, Stripe webhooks, produse/prices create, facturi emise. Trial-ul e setat dar nu e enforce-uit. Overage e calculat dar niciodată facturat.

Impact: Nu putem percepe bani. Toate promisiunile de pricing sunt literă moartă.

G2 P0 Inconsistență prețuri între landing pages

welcome.blade.php: 99€ / 299€ / Custom · home.blade.php + preturi.blade.php: ~49€ / ~149€ / ~399€. Fix rapid: șterge sau update welcome.blade.php (pare legacy).

G3 P0 API Sanctum tokens cu scope nelimitat *

SettingsController::generateApiKey() creează tokens cu abilities ['*'], fără rate limit pe endpoint, fără audit log. Un token scurs = control complet peste tenant.

G4 P0 Tenant isolation doar pe global scope

Niciun middleware la request boundary. Se poate bypassa accidental cu withoutGlobalScopes(). Recomand middleware EnforceTenantBoundary + audit de withoutGlobalScopes() în tot codul.

Sprint 1A — Google Calendar + Multi-Resource Bookings (5-8 zile)

Implementarea G23 cu support multi-calendar și dual-write CallbackRequest + Google.

Cazuri reale acoperite

  • Clinică medicală/stomato/veterinară — N medici, fiecare cu calendar și specializări diferite
  • Salon beauty — N stiliste cu skill-uri diferite (balayage / nails / facial)
  • Cabinet avocatură — N avocați pe specializări (penal / civil / comercial)
  • Agenție imobiliară — N agenți pe zone
  • Hotel / pensiune / B&B — N camere (fiecare cameră = resursă, ocupată pe perioade)
  • Service auto — N rampe / N mecanici
  • Restaurant — N mese sau N sloturi de delivery

Arhitectură multi-resource

bot (1) ─── (n) bookable_resources
                   ├── id, bot_id, name, slug
                   ├── kind: doctor | stylist | lawyer | agent
                   │       | department | room | table | bay | generic
                   ├── google_calendar_id (nullable)
                   ├── working_hours (json per zi)
                   ├── slot_duration_minutes
                   ├── buffer_before_minutes / buffer_after_minutes
                   ├── services_offered (json — routing pe servicii)
                   └── is_active

Un singur OAuth Google = N calendare. Tenant-ul mapează în UI: "Calendar Google «Dr. Popescu» → Resursa Sambla «Dr. Popescu»". Mai multe resurse pot puncta la același calendar dacă e cazul.

Tool pentru bot

book_appointment(resource_id_or_slug, start, duration, contact_name, contact_phone, service?, notes?)

Algoritm:
1. Resolve resource (după nume sau service requested)
2. Verifică disponibilitate (Google freeBusy SAU CallbackRequest local)
3. Persistă local CallbackRequest (sursa de adevăr — niciodată skipat)
4. Push Google paralel (job queued, retry 3x). La fail: sync_error, dar lead-ul rămâne.
5. Confirmă natural ("te-am programat la Dr. Popescu joi 14:00, primești SMS")

Plus tool secundar list_resources(service?) pentru întrebări de tipul "ce medici aveți pentru endodonție?".

Acțiuni concrete

  • Migration create_bookable_resources_table
  • Migration create_oauth_credentials_table
  • Migration add_resource_and_google_fields_to_callback_requests (bookable_resource_id, service_requested, google_event_id, external_calendar_provider, synced_at, sync_error)
  • Model BookableResource cu relații + scope forService()
  • Service GoogleOAuthService (exchange, refresh, revoke)
  • Service GoogleCalendarConnector (listCalendars, freeBusy, createEvent, deleteEvent)
  • Service AppointmentRouter (resolve + find next slot)
  • Job SyncCallbackToGoogleCalendar (queued, retry 3x backoff)
  • Tools book_appointment + list_resources în RealtimeSession + ChatCompletionService
  • Controllers: BookableResourceController (CRUD), GoogleIntegrationController (connect/callback/map/disconnect)
  • Views: dashboard/boti/{bot}/resurse/ (CRUD + working hours editor + color picker) și dashboard/integrari/google.blade.php
  • Update dashboard/callbacks/index.blade.php: coloană resursă + filter + badge sync
  • Tests Pest: 2 resurse cu calendare Google diferite → bookings paralele → ambele aterizează corect
  • Tests edge: Google quota → CallbackRequest creat + sync_error setat / tenant fără OAuth → totul local

Avantaje

  • ✅ Suportă clinică cu N medici, salon cu N stiliste, agenție cu N agenți
  • ✅ Routing automat pe baza serviciului cerut
  • ✅ Tenant poate folosi doar dashboard-ul intern (zero Google) și tot funcționează
  • ✅ Lead-ul nu se pierde niciodată — CallbackRequest local e sursa de adevăr
  • ✅ Migrare ușoară spre alți provideri în viitor
